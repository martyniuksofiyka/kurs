# PhotoStudio Manager

Настільна програма для автоматизації роботи фотостудії: бронювання залів, оренда реквізиту,
облік клієнтів і звіти. Курсова робота з дисципліни «Системне програмування».

Мова - C++17, інтерфейс - Qt Widgets, СКБД - SQLite (драйвер QSQLITE модуля Qt SQL).

## Можливості

- розклад залів на день у вигляді сітки; створення бронювання кліком по вільному часу;
- перевірка накладок бронювань і пошук найближчого вільного часу;
- облік реквізиту: доступна кількість рахується на конкретний проміжок часу
  з урахуванням інших бронювань та оренди;
- оренда реквізиту на винос, повернення, штраф за прострочення;
- автоматичний розрахунок вартості: надбавка у вихідні, накопичувальна знижка;
- клієнти з історією, імпорт та експорт CSV;
- 5 звітів з графіками, збереження в PDF і CSV, друк квитанцій та актів;
- ролі користувачів (адміністратор, менеджер), паролі зберігаються як SHA-256 з сіллю;
- резервна копія БД, журнал дій.

## Структура проєкту

```
CMakeLists.txt          збирання через CMake (основний спосіб)
PhotoStudio.pro         збирання через qmake (альтернатива для Qt Creator)
src/main.cpp            запуск, параметри командного рядка
src/core/               предметна логіка та доступ до даних (без GUI)
    pricing.*           розрахунок вартості (суми в копійках)
    scheduling.*        перевірка накладок, доступність реквізиту, пошук вільного часу
    database.*          підключення до SQLite, транзакції, запити, навчальні дані
    session.*           поточний користувач і налаштування студії
    exporter.*          CSV, PDF, друк
src/ui/                 вікна та віджети інтерфейсу
db/schema.sql           схема БД (вбудовується в програму як ресурс)
db/clients_example.csv  приклад файла для імпорту клієнтів
resources/              іконки, стилі, довідка
tests/tst_core.cpp      автоматичні тести (Qt Test)
tests/test_protocol.md  план тестування і фактичні результати
docs/                   пояснювальна записка та супровідні документи
```

## Збирання

### Qt Creator (Windows, macOS, Linux)

1. Відкрити `CMakeLists.txt` (або `PhotoStudio.pro`) у Qt Creator.
2. Вибрати комплект Qt 6 (або Qt 5.14+) з потрібним компілятором.
3. Зібрати (Ctrl+B) і запустити (Ctrl+R).

### Командний рядок

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=<шлях до Qt>   # напр. C:/Qt/6.9.3/mingw_64 або ~/Qt/6.9.3/macos
cmake --build build
ctest --test-dir build --output-on-failure            # запуск тестів
```

Для Visual Studio додати `--config Release` до команд збирання й тестування.

### Комплект запуску для Windows

Після збирання в режимі Release скопіювати `PhotoStudio.exe` в окрему папку й виконати:

```bat
windeployqt --release PhotoStudio.exe
```

Утиліта додасть потрібні DLL, плагін `platforms/qwindows.dll`, `sqldrivers/qsqlite.dll`,
`iconengines/qsvgicon.dll` і `printsupport`. Без `sqldrivers/qsqlite.dll` програма не зможе відкрити БД.

## Запуск і база даних

```
PhotoStudio [--db <файл>] [--reset-demo]
```

- без параметрів БД зберігається в стандартному каталозі даних користувача:
  - Windows: `%APPDATA%\PhotoStudio\PhotoStudio\photostudio.db`
  - macOS: `~/Library/Application Support/PhotoStudio/PhotoStudio/photostudio.db`
  - Linux: `~/.local/share/PhotoStudio/PhotoStudio/photostudio.db`
- `--db <файл>` - використати інший файл (створюється, якщо його немає);
- `--reset-demo` - очистити БД і заповнити навчальними даними.

Під час першого запуску схема створюється з `db/schema.sql`, а база заповнюється навчальними
даними. Повний шлях до файла БД показано у вікні «Довідка → Про програму».

Навчальні облікові записи:

| Логін | Пароль | Роль |
|---|---|---|
| admin | admin123 | адміністратор |
| manager | manager123 | менеджер |

### Відновлення навчальних даних

Один із способів:
- меню «Файл → Відновити навчальні дані» (лише адміністратор);
- запуск з параметром `--reset-demo`;
- видалити файл `photostudio.db` - під час наступного запуску базу буде створено заново.

Навчальний набір однаковий при кожному відновленні: бронювання генеруються з фіксованим
зерном відносно поточної дати (5 тижнів назад і 2 тижні вперед).

### Журнал

Дії користувачів і помилки записуються у `photostudio.log` у тому ж каталозі даних.
Паролі в журнал не записуються.

## Відомі обмеження

- одне з'єднання з БД і один користувач одночасно (локальна SQLite);
- бронювання не може переходити через північ - лише в межах робочого дня студії;
- ціни зберігаються в копійках, розрахунки виконуються цілими числами;
- оплата не інтегрована з платіжними системами, фіксується лише сума передплати;
- для друку потрібен встановлений принтер (збереження в PDF працює без нього).
